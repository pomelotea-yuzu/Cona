# 产品决定记录

记录**已确定**的产品决定与**待定**项；日期为决定日，改动请标注版本与日期。
产品优先级：**安全可控、易用美观**。来源：用户与 Agent 在 M0 验证期间的讨论（2026-10-18）。

## 已确定

### 1. 安装形态与提权

- 产品**允许像普通软件一样下载安装**；**首次安装（或一次性供给）提权一次可以接受**。
- **日常运行不需要提升权限**（本轮实测支持：日常执行全程无提权）。
- 为什么必须有一次：卷根读属性／遍历授权、运行时安装目录的只读授权都不是普通用户能做的
  （见 [环境前提与一次性供给](../development/environment-and-provisioning.md)）。
  这与任何装到 `Program Files`／写 HKLM／装服务的软件一致，不算例外。

### 2. 目录布局与授权分区

- **安装目录与数据目录可以分开，推荐分开**：安装目录放可执行程序与**随包运行时**（只读授权）；
  数据目录由用户选择，放工作副本、版本存储、账本、日志、配置（读写授权），卸载默认保留。
- **"只读运行时区"与"可写数据区"必须在授权上分开**，不得合并为一套读写权限——否则受限进程（Agent）
  会同时获得改写产品自身可执行文件的能力。两者物理上可以同根不同子目录，也可以完全分离。

### 3. 数据落点

- **不把用户数据写进 `APPDATA` 之类位置，用户数据必须能放在用户指定的位置**（实测：完全可以做到，
  原型即把所有数据放在实验根下）。
- 容器启动时**必须显式提供** `USERPROFILE`／`APPDATA`／`LOCALAPPDATA`（缺任一 `CreateProcess` 失败）；
  指向用户指定目录后，容器会在其下追加 `Packages\<容器名>\AC`，不会回落到真实 `%LOCALAPPDATA%`。
- **唯一例外**：Windows 自建的容器身份档案目录 `%LOCALAPPDATA%\Packages\<容器名>`，位置由 API 决定。
  产品应**保留**该档案（只在卸载时删除），并在产品说明中列出这一处痕迹。

### 4. C 盘偏好

- **默认不主动碰 C 盘**——这是产品默认行为的偏好，**不是对用户的限制**：默认建议安装目录与数据目录放在
  非 C 盘，运行时随包，因此卷根授权与数据写入都落在该盘。
- **用户自行选择把安装目录或数据目录放到 C 盘，属用户自由，产品不禁止**；技术前提不变，只是目标盘变成 C。
- 按当前路线，**产品默认造成的 C 盘痕迹只有容器身份档案一处**。原型里对 `C:\Program Files\Git` 的
  只读引用属于"图方便"，产品形态应改为随包运行时后消除。

### 5. Git 的处置（已认定事实，待定方案）

- 已认定：**AppContainer 内 Git for Windows 不可用**（详见 [隔离原语实测](../research/windows-isolation-primitives.md)）。
- 方案待定：容器外可信 Git 服务，或接受 Git 不在隔离范围内并写入产品说明。

|---|---|
| 安装目录与数据目录的**默认具体位置** | 是否给出一组推荐路径，或首次运行时由用户选择 |
| 容器身份档案能否重定向到非 C 盘 | 未验证的想法（junction 方案），需做小实验后再定 |
