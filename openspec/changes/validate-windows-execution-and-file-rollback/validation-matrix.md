# Windows 执行与文件回退验证矩阵

状态：验证计划，全部用例**未测**。提案建立或 OpenSpec 校验通过不改变本表运行状态。

## 运行与证据约定

- 仅使用专用实验根、合成项目、假凭据、可检查的测试端点；任何破坏性动作都要先验证绝对目标及实际对象在实验范围内。
- 每个 run 保存 `environment.json`、`results.json`、脱敏日志、文件前后清单、进程事实及必要服务端接收记录；名称是建议，字段要求必须保留。
- 每个结果包含 `caseId`、`runId`、代码／构建版本或未提交内容指纹、环境与工具版本、有效策略、输入、预期、实际、开始／结束时间、证据路径及状态。未满足前提记为受阻，不能记为通过。
- E 表示执行与隔离（Execution），F 表示文件版本与恢复（File），P 表示安装和资源开销（Provisioning / Performance）。本轮串行执行样例；跨任务反例使用合成资源和身份，不构成两个活动 run 的并发一致性验证。
- 安全反例验证拒绝及目标未变；正例验证真实成果与退出状态。只看到程序报错不足以证明授权边界有效。
- 存在破坏、外发或路径替换的样例不得使用真实用户文件、生产服务或真实秘密。联网只开放执行该用例所需的测试端点和固定依赖源。
- 生成证据默认保留本地。整理入仓库的结论应脱敏，不包含凭据、个人路径、资料原文和缓存大文件。

E11 的观察参数在 run 开始前固定：心跳周期默认 100ms、采样周期默认 200ms，核查进程终态后观察至少 10 秒且不少于 20 个心跳周期。结果记录配置、实际持续时长、采样时间和文件变化；睡眠或观察中断时记为受阻并重测。此窗口用于样例证据可比性，不是停止响应时间的验收阈值，也不能替代进程身份核查。

## 路线判定规则

研究结论与产品能力放行分别记录。所有必要用例及子项都需要实际证据；缺证据、受阻或未测不能当作通过。

| 建议 | 判定口径 | 后续动作 |
|---|---|---|
| 采用 | 必要安全、兼容性和文件恢复用例全部通过，安装与资源报告完整；用户已认可相应安装与资源负担 | 可以建议正式集成已验证范围，仍受文档引擎、正式发送链路等后续门槛约束 |
| 调整 | 已知问题有具体修复或配置方案，能够维持安全要求并保留已定的必要工作流，资源负担也存在可验证的改进路径 | 仅继续原型实验；修复后重跑受影响的正反例，未通过前不放行 |
| 暂缓 | 出现安全或文件保护硬约束失败，必要条件缺失且无可验证解决路径，或无法在安全边界内完成必要工作流 | 暂缓对应能力进入正式产品；保留证据，评估替代后端或后续提案 |

安全与数据保护失败具有否决效力。例如 E04 越界、E06 路径替换、E07 秘密或接口越权、E09 网络绕过、E11 停止失控、E12 隔离失败仍执行、E14 未授权启动以及 F01–F07 中的文件破坏／误覆盖，任一失败都暂缓对应能力；其他用例发现同类违规也同样处理。不能用“整体利大于弊”或较小资源开销抵消。允许继续修复实验不等于允许产品使用。

兼容性失败如能通过收紧后的明确配置修复且不扩大权限，可建议调整；若只能靠放宽隔离或取消必要工作流才能运行，则暂缓。若需要改变已确认的产品范围，另行提出具体取舍。

当前没有已批准的资源数值阈值。Agent 提供测量事实、开销来源和优化建议，用户根据脱敏报告判断安装权限、额外服务和资源负担是否可接受；用户尚未判断时标记“技术证据齐备，资源接受度待定”，不得写成已认可或最终采用。无需在提案阶段预先选择数值。

## 结论模板

后续执行完成时新增实际结论报告，本文件不预填结果。报告至少包括：

1. 执行日期、环境、构建指纹及证据位置。
2. 各用例的通过／失败／受阻／未测分布，失败或缺证据门槛的具体 ID。
3. 已证明的能力与实际限制，避免将假数据网关扩大为完整隐私能力、将替身扩大为文档引擎兼容。
4. 安全、兼容性、恢复与资源负担的独立判断；未批准数值阈值时只报告测量结果及建议。
5. 按上述判定规则给出采用／调整／暂缓建议、硬约束失败项、适用范围与复测条件；任何技术修复建议都不解除尚未通过的门槛。失败可以形成有效研究结论。
6. 分别记录安装与资源负担的用户判断（待定／接受／需调整）、需要修改的设计与后续 change；不冒充用户已接受数值，不重新询问已确定的原则。

本 change 完成不代表整个 M0 结束：选定文档引擎的受限进程验证、DOCX/PDF 编辑与排版、正式上下文发送链路以及界面原型各有后续验证责任。
