# Design

## Context

当前工作区只有产品设计文档及本次建立的 OpenSpec，没有应用或执行器代码。动机与范围见 [proposal.md](proposal.md)，行为要求见 [执行原型规范](specs/windows-execution-prototype/spec.md)和[恢复原型规范](specs/workspace-recovery-prototype/spec.md)。

本 change 是 M0 的第一项验证，不是完整 M0 或首版实现。技术候选仍是 AppContainer、精确 ACL、Job Object；微软接口文档只说明机制，实际组合的权限、兼容性与开销需要本机证据。

## Goals / Non-Goals

**Goals:**

- 通过确定性测试程序和真实 Node／pnpm／本地 Git 样例，分别验证允许的工作成功和越界尝试失败。
- 将宿主、执行器、副本、受保护版本和交付目标分开，验证每一条跨边界入口。
- 为采用、调整、暂缓原生方案提供可复现证据，而非靠模型自述判断成功。
- CLI 原型输出简洁状态、实际范围、差异和停止／恢复结果，为后续易用界面提供状态契约。

**Non-Goals:**

- 本次不接真实模型、不使用真实密钥、不对真实项目做破坏性试验。
- 不建设完整任务调度、应用界面、持久数据库、插件系统或跨平台执行后端。
- 不承诺任意程序可用、任意文件元数据可保真恢复、任意外部副作用可撤销。
- 不自研驱动、隔离内核或虚拟机；不部署 CubeSandbox。
- 不验证两个活动 run 并发时的版本存储、交付账本与停止管理一致性；本轮串行运行样例，“其他任务”使用隔离的合成资源和身份，只证明跨任务访问拒绝。正式多任务调度仍需后续并发验证。
- 不验证绕过工作副本、由受限执行器直接修改原项目的工作模式；原项目写入只经可信交付与恢复服务。

## Decisions

### 1. 原型独立于正式桌面应用

原型代码目录约定为 `prototypes/windows-execution/`。执行器先以 C++／Win32 小程序直接调用系统接口，测试驱动使用 Node 标准库和固定样例，避免为一次接口验证引入桌面壳或大型服务。此选择只服务 M0，不锁定正式执行器语言。

实施先检查已安装编译器、Windows SDK、Node、pnpm、Git 和 Windows 版本，记录实际版本与安装权限。工具链不足时记录阻塞，不在提案阶段安装。正式应用继续使用现有技术设计默认。

环境报告分别列出首次设置与日常运行所需的提升权限、依赖和额外服务；未知要求不能默认为“不需要”，缺少必要条件记为受阻。已有管理员终端中的成功不等于普通用户可运行，权限前提必须随证据保存。

备选是直接使用 PowerShell 或独立 worker；它们可以作为测试载荷，但无法单独证明操作系统访问边界。备选虚拟化仅在原生方案不满足要求后另行评估。

### 2. 明确信任边界与启动顺序

可信测试宿主保管授权、假凭据、日志、版本存储及交付账本。受限进程只能访问当前样例的工作副本、专用临时／缓存和明确列出的只读运行时；原项目、其他任务、宿主状态与备份不授予写权限。

执行请求至少携带任务／运行标识、参数数组、工作根、可读写资源、网络模式、超时及停止策略。可执行文件和参数分开传递；业务层不拼接任意宿主 Shell。

正常请求路径也要测试无授权、授权已失效、范围外请求及任务身份不匹配；这些请求必须在启动载荷前被拒绝，不能只靠初始化故障注入替代。

启动流程为：验证授权及路径身份 → 建立受限资源与环境 → 创建受限且挂起的进程 → 完成 Job 归属与隔离核验 → 恢复执行。任一步失败都销毁未运行载荷并给出原因；没有“用户权限继续运行”的兜底分支。

Job 配置禁止 breakaway，并测试关宿主时的 kill-on-close；这些设置仍需要实际验证，不能只读配置位判定成功。仅继承必要句柄，使用明确的环境变量列表，测试普通命令、Shell、安装脚本及其派生进程继承边界。

### 3. 路径授权覆盖真实对象

使用规范化路径、实际打开对象身份和受限 ACL 共同检查，不依赖字符串前缀。测试大小写、相似前缀、UNC／设备路径、备用数据流、短路径可用性、符号链接、junction、硬链接及检查后替换目标。

原型对未实现安全语义的 reparse point、外部指向和特殊对象明确拒绝导入／交付／恢复，不遍历到授权范围外。受管理副本、版本存储与原项目之间不共享可写硬链接。受保护数据所在目录的实际访问权限由反例验证；系统公共可读资源等无法收紧的范围须列出，不能笼统宣称整机文件完全不可见。

### 4. 离线执行与联网执行分开验证

先建立默认拒绝直接联网的执行配置，再单独实验最小受控出口：宿主限定接收端、方法及目标策略，通过绑定任务身份的窄通道提供访问；执行器拿不到模型 API 凭据，接口不接受任意宿主命令或路径。

联网原型的验证顺序是测试服务 → 固定依赖源上的 pnpm 安装 → 安装脚本绕过尝试。具体通道与 AppContainer 的兼容性是本次实验问题，不预先断言普通代理一定可用。若需要宽泛 loopback 豁免、无约束网卡权限或管理员服务才能工作，记录新增暴露面、权限与开销，不能以“代理配置成功”代替出口限制证明。

直连 IP、DNS、IPv4／IPv6、代理变量改写、本机其他端口和跨任务调用都要测试。若无法保证受控出口，联网结论为未通过或受阻；离线成功不代表完整开发场景可放行。允许访问一个域名也不能证明该域名不会接收数据外传。

模型资料发送仅用假数据和捕获请求的测试网关核对：本机读取许可不能使排除材料进入请求；API 认证秘密留在宿主，不进入载荷。真实上下文、记忆、摘要和 provider 集成留在后续正式能力验证中，本次不声称完成整个模型隐私链路。

### 5. 文件版本优先验证正确性

为每个样例建立独立的 `source/`、`workspace/` 与可信 `versions/`、交付账本。前者模拟原项目；全部都位于专门的实验根，真实工作区和用户资料不作为破坏目标。

M0 优先采用完整清单与内容寻址的受保护文件副本，文件内容按 SHA-256 校验。先保存原始基线，再在执行批次前与批次结束、阶段完成、用户保存、交付等节点建立版本。清单区分文件存在、删除、目录及受支持元数据；空文件和二进制按字节处理，不能只保留文本补丁。

快照前停止相关写入并确认进程终态，扫描与复制期间发现版本变化则失败或重试，不能发布不一致版本。批次中途崩溃时依靠批次前恢复点和操作账本核查；不承诺逐条命令的时间旅行。文件大小与数量上限需显式检查，超过能力时不能显示已保护后再继续高风险写入。

使用全清单便于观察 Shell 和转换程序的实际文件变化；只记录文件工具事件会漏掉项目脚本修改。正式性能优化以后单独评估，不能用与原文件共享可写内容的硬链接节约空间。

原型首先支持普通目录和普通文件，记录文件内容及必要属性。特殊链接、备用流、加密／稀疏等未支持语义需识别并阻止相关承诺；不以静默丢弃代替恢复。Git 为兼容性样例，恢复本身不依赖项目有 Git；外部 gitdir／alternates 等不在初始授权内的引用要拒绝或另行授权。

### 6. 交付与回退使用相同的版本核对原则

导入时保存原项目基线。交付时基于基线、当前原项目和成果形成新增／修改／删除计划，先展示范围、核对授权和版本，再保存当前目标恢复点，最后执行。

原型先验证显式交付；正式产品在已批准范围内可以按既定流程交付，无需为每个普通文件反复确认。Agent 只能提出交付请求，不能直接绕过可信服务写原项目。

恢复前停止相关执行，核对目标路径身份和实际版本。新增文件只有在内容仍对应本次操作时才能删除；后续用户改动保留并报冲突；恢复被删文件时也不能覆盖后来同名新文件。恢复前的当前状态同样保留版本，避免错误恢复失去依据。

多文件操作不假设全目录原子性。按文件使用安全替换、恢复点及持久操作账本，复核与写入之间防止路径替换和并发写入；不能安全核对时拒绝该项。中断后展示已完成、未完成、冲突和未知项，再决定继续或恢复；不无条件重放整个操作。

### 7. 停止、崩溃与恢复必须可观察

记录 `preparing`、`running`、`stopping`、`stopped`、`failed`、`interrupted`、`unknown` 等原型状态及时间。取消后先发停止请求，到时限后终止受管理进程，并对照进程身份、创建时间及 Job 事实核查后代，避免仅靠父进程或复用 PID。

停止验证使用可配置且在 run 开始前固定的观察窗口：默认心跳写入周期 100ms、采样周期 200ms；核查进程终态后持续观察至少 10 秒且不少于 20 个心跳周期。先验证停止前心跳实际产生，再记录窗口配置、实际持续时长、采样时间与文件变化；睡眠或观察中断使窗口无效，需重测或记为受阻。它用于固定测试的可比性，不是停止时延承诺，也不能证明任意延迟触发行为不存在。

宿主崩溃、系统重启或回执丢失时，重开先核查残留与文件事实；无法判断的保持未知，禁止自动重放有副作用命令。杀进程不能撤销已发生的文件写入，文件恢复需另行执行。

### 8. 验证结果与放行结论分开

[validation-matrix.md](validation-matrix.md) 规定必要案例及证据格式。运行输出目录约定为 `output/windows-execution-validation/<run-id>/`，只使用合成资料；生成物不直接当作提案正文或默认上传到仓库。长期结论使用脱敏报告，引用可核对的用例、环境与运行版本。

每项区分通过、失败、受阻和未测。安全负例、正常工作、恢复和资源开销分别报告；不能因负例全被拒绝而忽略正常工作也无法完成。

采用／调整／暂缓按矩阵的路线判定规则处理：任何越权、隔离失败仍启动、停止失控或文件恢复破坏当前内容的反例失败，立即暂缓对应能力放行；兼容性问题只有在维持安全要求、保留必要工作流的条件下才能建议调整。资源及安装负担由用户依据脱敏报告判断可接受性，Agent 提供事实和建议，不自行虚构阈值。判定“调整”只允许继续实验，不能绕过失败的安全门槛；修复后须重测受影响的正反例。

允许以否定结论结束研究，但通过安全与兼容性门槛之前不开放对应产品能力。未测和受阻的必要门槛必须列为未解决项，并指定后续工作；不能勾选尚未执行的任务来归档。已有证据足以否定路线时，可明确记录剩余实验因路线终止而取消，保留它们未执行的事实与后续替代提案。

资源报告记录同机空载基线、冷／热启动、空闲／工作峰值、磁盘及安装权限，至少重复五次并保留原始样本及汇总；区分宿主、执行器、项目工具和缓存。该次数服务可复现观察，不代表统计安全性或跨机器性能结论。当前无已批准的数值阈值，结果只能支持负担判断，不能伪称达到某个“轻量标准”。

选定文档转换器后的真实受限进程兼容性由单独文档 change 补充；本 change 不得单独解除第 12.3 节的文档工具门槛。

## Risks / Trade-offs

- 原生隔离与 pnpm／Git 不兼容 → 将具体失败动作、额外权限及替代路线写入结论，不静默放宽。
- 安装脚本借已授权网络发送材料 → 默认限制材料可见范围和出口，记录允许端点仍有的外发风险；网络白名单不等于数据防泄漏证明。
- 宿主接口成为逃逸入口 → 验证任务身份、授权、动作和版本，反例覆盖跨任务与任意路径请求。
- 全量扫描与内容存储开销较高 → 单独测量文件数量、依赖缓存和版本磁盘增长，保持正确性后再优化。
- Windows 权限、版本、文件系统与安全软件影响结果 → 记录环境及范围，不把一台机器通过扩大为全部 Windows 兼容。
- 假凭据与测试网关只覆盖部分隐私路径 → 明确结果适用范围，后续模型上下文集成继续验证，不宣称完整防泄漏。
- 回退时存在外部编辑或多文件操作中断 → 基线检查、当前状态备份、逐项账本与冲突保留，不承诺任意状态一键无损恢复。

## Migration Plan

当前只新增提案和规范，无应用数据迁移。后续原型只在明确的实验根生成测试数据，保留每个 run 的资源清单；结束时先确认所有实验进程终止，再按经过绝对路径与对象身份核验的清单清理，不能递归删除计算所得的未知目标。

形成结论后，将可复用接口和已证实约束交给正式执行能力 change；原型不会自动成为正式后端。失败时保留脱敏证据与替代建议，不影响现有设计文档、其他项目或原仓库。
