# Proposal

## Why

Cona 已确定以“安全可控、易用美观”为工作重点，首版先在 Windows 运行，默认使用受管理工作副本并支持文件改错回退。当前 AppContainer、精确 ACL 与 Job Object 的组合尚未验证；在建设真实命令执行能力前，需要证明它既能约束错误命令及项目脚本，又能完成常见开发工作，且安装与资源负担可接受。

## What Changes

- 建立可独立运行的 Windows 小型验证原型，验证启动前授权、文件与凭据隔离、受控联网、子进程与完整停止；隔离失败时拒绝执行。
- 验证受管理工作副本、受保护的文件基线与版本、差异、受控交付，以及副本和原项目文件的回退；覆盖命令实际产生的新增、修改和删除。
- 使用专用测试目录、假凭据和本机测试服务建立正反例，避免破坏真实项目或发送真实资料；验证本机读取不自动授予模型资料外发能力。
- 交付可复现验证矩阵、运行证据和采用／调整／暂缓的结论，实测安装权限、依赖、启动、内存与磁盘开销。
- 本次先建立提案；后续原型实现按任务清单推进。所有执行与测量任务当前均未完成，不以文档校验代替安全验证。

## Capabilities

### New Capabilities

- `windows-execution-prototype`：验证 Windows 受限执行、网络与宿主接口、进程生命周期和证据输出的可观察契约。
- `workspace-recovery-prototype`：验证受管理工作副本的文件版本、受控交付、冲突保护与可核查恢复的可观察契约。

### Modified Capabilities

无。当前 `openspec/specs/` 中没有既有能力规范；上述规范限定本次技术原型，不代表完整产品已实现。

## Impact

- 本 change 的提案产物包括 OpenSpec 配置、提案、设计、规范、任务清单与验证矩阵；实现阶段另交付原型、运行证据和路线结论。
- 同步维护：现有两份设计文档的提案状态和仓库信息已更新，此项不代表原型交付完成。
- 原型阶段约定代码放在 `prototypes/windows-execution/`，合成样例放在该目录的 `fixtures/`，运行证据放在 `output/windows-execution-validation/<run-id>/`；以上运行目录本轮不创建、不执行。
- Windows 系统接口及原生构建工具链需要后续验证；本次不安装 SDK、驱动、虚拟机、容器或文档引擎，不选择未经证实的性能数字。
- 不需要真实模型 API 或真实凭据；网络与模型发送边界可先用测试服务验证。不得把测试输出中的秘密写进可提交证据。
- DOCX/PDF 编辑与排版验证另建 change；本次仅检查受限执行器运行文档工具的接口条件，选定转换工具后的真实进程兼容性仍是后续放行门槛。
- 不建设正式 Electron 应用、跨平台后端、远程执行或通用沙箱平台；本次不复制 ReBaseAgent 代码，也不提交或推送仓库。
